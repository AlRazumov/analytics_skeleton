# Демо на данных мока

> **Данные синтетические.** Их генерирует `MockAdapter` (детерминированно по
> seed): названия товаров — «Product N», суммы и остатки — условные. Это
> витрина возможностей, а не результаты реального бизнеса.

## Как поднять демо с нуля (Sail)

```bash
cp .env.example .env
# DB_* в .env.example уже под Sail (PostgreSQL); поправить APP_URL — адрес приложения.
# Необязательно (значения по умолчанию): ANALYTICS_SOURCE=mock,
# ANALYTICS_MOCK_PROFILE=small|medium, ANALYTICS_MOCK_SEED=42,
# ANALYTICS_MOCK_SELLER_COVERAGE=full|partial|none (сколько сделок несут продавца)

./vendor/bin/sail up -d
./vendor/bin/sail artisan key:generate
./vendor/bin/sail artisan migrate                 # команда demo:install миграции не запускает
./vendor/bin/sail artisan demo:install --email=demo@example.com
```

`demo:install` работает только при `ANALYTICS_SOURCE=mock`: синхронизирует
справочники (`reference:sync`), считает метрики (`metrics:calculate`) за всю
историю мока одним прогоном и, если передан `--email`, создаёт пользователя
(пароль — минимум 12 символов — запрашивается интерактивно, паролей по
умолчанию нет). Если таблиц нет, команда подскажет `php artisan migrate`.
Повторный запуск безопасен: снэпшоты за тот же период пересчитываются заново,
существующий пользователь не меняется.

Войдите на `/login` под созданным пользователем — откроется `/dashboards/overview`.

## Профили

| Профиль | Товаров | История | Расчёт `demo:install` | Примерное время |
|---------|---------|---------|-----------------------|-----------------|
| `small` | 50 | 12 месяцев (2025-09…2026-08) | 12 месяцев | секунды |
| `medium` | 500 | 24 месяца (2024-09…2026-08) | 24 месяца | около минуты |

Профиль задаётся `ANALYTICS_MOCK_PROFILE` (по умолчанию `medium`). Сравнение
«год к году» доступно только там, где есть данные за тот же месяц прошлого
года: на `small` его нет (в интерфейсе переключатель не показывается), на
`medium` — для месяцев с 2025-09.

## Что где видно

| Страница | Что на ней |
|----------|------------|
| `/dashboards/overview` | Обзор продаж: KPI выручки, график динамики за 6 месяцев, график «год к году», топ-20 товаров по выручке за окно (месяцы колонками) |
| `/dashboards/abc-xyz` | Матрица ABC/XYZ: число товаров и выручка в каждой ячейке; фильтр по категории `?category=` |
| `/dashboards/stock` | Остатки: график «Неликвиды по возрасту» и таблица неликвидов; график «Дни до обнуления» и таблица риска дефицита. CSV: `/dashboards/stock/export/dead-stock`, `/dashboards/stock/export/stockout-risk` |
| `/dashboards/top-products` | Топ и «наименьшая выручка среди проданных за месяц» с графиком топа; переключатель сравнения: с предыдущим месяцем / с тем же месяцем прошлого года (`?base=year_ago`). CSV: `/dashboards/top-products/export` — все проданные товары |
| `/dashboards/categories` | Выручка по категориям за месяц: столбчатый график, таблица с долей, сравнением (с предыдущим месяцем / с тем же месяцем прошлого года, `?base=year_ago`) и числом проданных товаров; помесячная динамика категорий за 12 месяцев. На моке 5 категорий, товары распределены по ним случайно. CSV: `/dashboards/categories/export` |
| `/dashboards/turnover` | Оборачиваемость в штуках: распределение по корзинам, самая низкая и самая высокая. CSV: `/dashboards/turnover/export` — все товары |
| `/dashboards/transfers` | Рекомендации перемещений между складами: сводка (дефицитные пары / с рекомендацией / без донора) и таблица «откуда → куда, сколько, покрытие до → после». Сценарий дисбаланса мока (`imbalanceProducts`): 2 товара на Small, 5 на Medium. CSV: `/dashboards/transfers/export` — все рекомендации |
| `/dashboards/sellers` | Продавцы: все продавцы за месяц, рейтинг по метрике `?metric=` (количество/сумма продаж, средний чек, доля, продаж в активный день, изменение к пред. месяцу), строка «Без продавца», график; ссылка «Скачать CSV» (`/dashboards/sellers/export`, та же таблица) |
| `/dashboards/products/{id}` | Карточка товара (открывается по названию товара в таблицах топа, остатков, оборачиваемости и перемещений): категория, ABC/XYZ-класс, показатели месяца (выручка к пред. месяцу, продано, остаток, оборачиваемость, дней без продаж, потерянные продажи), выручка и штуки по месяцам за 12 месяцев, склады (дни до обнуления, склады без продаж) |

Над страницами — плашка «Данные рассчитаны … за …» (журнал запусков
`metrics:calculate`, см. README, «Регулярный пересчёт метрик»); до первого расчёта после
обновления её нет.

Месяц переключается ссылками «← предыдущий / следующий →» над страницей
(ближайшие месяцы, за которые есть данные этой страницы; фильтр категории,
база сравнения и метрика сохраняются) или параметром `?period=month:YYYY-MM`. CSV-выгрузки
(ссылка «Скачать CSV» под таблицей) содержат все строки таблицы за тот же
период, а не только показанные на странице; формат — под русский Excel
(UTF-8 с BOM, `;`, десятичная запятая). На «Топ товаров», «Остатках»,
«Оборачиваемости» и «ABC/XYZ» есть фильтр по категории (`?category=`, форма над
таблицами): фильтруются таблицы, графики и выгрузка (на ABC/XYZ — товары в
ячейках матрицы, классы остаются посчитанными по всему ассортименту); на странице «Категории»
название категории ведёт на её топ товаров. Страницы и виджеты
можно скрыть флагами — см. [features.md](features.md). Безопасность и создание
пользователей — [security.md](security.md).

## Ограничения демо

- Данные не связаны ни с каким реальным источником; реальные адаптеры
  (Bitrix24, 1С) в проекте не реализованы.
- Значения мока фиксированы seed'ом: разные `ANALYTICS_MOCK_SEED` дают
  разные, но такие же синтетические данные.
- Деньги на страницах — условные единицы мока.
- Сделки и движения склада мок генерирует независимо: в карточке товара
  выручка месяца может соседствовать с «продано 0 шт.» и неликвидом (например,
  `prod-1` — товар сценария неликвидов, у которого сделки продолжаются).

## Как обновить Chart.js

Chart.js лежит локально: `public/vendor/chartjs/chart.umd.min.js` (UMD-сборка,
та же, что отдаёт CDN по `chart.js@4`) и `LICENSE.md` (MIT); подключён в
`resources/views/components/layouts/standalone.blade.php` через `asset()`.
Текущая версия — 4.5.1 (в заголовке файла: `Chart.js v4.5.1`). Пакеты в проект
не добавляются — файл берётся из официального npm-дистрибутива:

```bash
cd "$(mktemp -d)"                       # временная папка вне проекта
npm pack chart.js@4.x.y                  # нужная версия 4.x
tar xzf chart.js-4.x.y.tgz
sha256sum package/dist/chart.umd.min.js  # запишите хэш в отчёт/коммит
cp package/dist/chart.umd.min.js <проект>/public/vendor/chartjs/chart.umd.min.js
cp package/LICENSE.md            <проект>/public/vendor/chartjs/LICENSE.md
```

После замены проверьте страницы с графиками в браузере и обновите версию в
этом разделе и в тесте `tests/Feature/NoExternalAssetsTest.php`. Карта
`chart.umd.min.js.map` не копируется (в консоли браузера возможно
предупреждение об отсутствии source map — на работу не влияет).
