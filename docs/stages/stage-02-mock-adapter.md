# Этап 02: MockAdapter

Зависит от: 01 (core-модели + контракт `DataSourceAdapter`).

## Задача

Реализовать `MockAdapter implements DataSourceAdapter` — потоковый
генератор тестовых данных (без обращения к реальным источникам),
достаточный для разработки и тестирования `widgets/` (Этап 03) без
подключения Bitrix24/1С.

Ключевые требования:
- Все три `fetch*`-метода (`fetchProducts`, `fetchDeals`,
  `fetchStockMovements`) возвращают `Generator`, ничего не собирается
  в памяти целиком.
- Данные воспроизводимы по паре `(profile, seed)` и не зависят от
  порядка/истории вызовов других `fetch*`-методов (никакого общего
  состояния между вызовами).
- Несколько профилей масштаба (объём продуктов/сделок/складов), чтобы
  проверять поведение виджетов и производительность на разных объёмах.
- Сезонность и аномалии спроса, чтобы данные не были равномерным шумом.
- Отдельный сценарий дисбаланса склада между филиалами (перепроизводство
  на одном складе / дефицит на другом по одному товару) — как
  тестовый контракт для будущего алгоритма рекомендаций межфилиального
  перемещения (вне scope этого этапа).
- `Transfer`-движения используют пару `warehouseId`/`toWarehouseId` по
  инварианту `StockMovement`, добавленному постфактум на Этапе 01.

## Что не входит в этот этап

- Artisan-команда для ручного запуска генератора.
- Отдельная сущность `Location`/`Warehouse`.
- Сам алгоритм рекомендаций межфилиального перемещения — только данные.
- `widgets/` (Этап 03).
- Калибровка профилей под объёмы конкретного клиента.
