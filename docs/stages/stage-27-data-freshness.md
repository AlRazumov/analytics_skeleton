# Этап 27: индикатор свежести данных

Идея из «Следующих шагов» roadmap (п. 4). Зависит от этапа планировщика
(ночной `metrics:calculate`, PR #14); реальные адаптеры не нужны.

## Что делаем

- Журнал запусков `metrics:calculate` — таблица `metrics_runs` (источник,
  период, статус running/success/failed, число снэпшотов, ошибка, время).
  Запись — вне транзакции расчёта, чтобы упавший запуск остался в журнале.
- Плашка над страницами дашбордов: «Данные рассчитаны <время> за <период>».
  Предупреждение, если последняя попытка после успешного расчёта упала, если
  расчёт идёт сейчас, и если успешный расчёт старше порога (по умолчанию 36 ч).
- Часовой пояс времени на плашке и порог — настройки
  (`ANALYTICS_DISPLAY_TIMEZONE`, `ANALYTICS_STALE_AFTER_HOURS`).

## Что не входит

Уведомления (почта/мессенджер) об упавшем расчёте, страница истории
запусков, текст ошибки на плашке (он в журнале и `storage/logs/metrics.log`).

Детали и результаты — `docs/reports/stage-27-data-freshness.md`.
