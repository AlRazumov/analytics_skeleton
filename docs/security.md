# Безопасность инсталляции

## 1. Что защищено, а что нет

- **Standalone-часть** (страницы на `StandaloneLayout`: `/dashboards/overview`,
  `/dashboards/abc-xyz`, `/dashboards/stock`, `/dashboards/top-products`,
  `/dashboards/turnover`) требует входа:
  гость перенаправляется на `/login`. Вход/выход — `laravel/fortify` с
  отключёнными фичами (`features = []`): нет регистрации, сброса пароля,
  верификации email, 2FA. Вход ограничен 5 попытками в минуту на пару
  email + IP.
- **iframe-роуты не защищены** и не будут защищены до этапа Bitrix24Adapter
  (их авторизация — часть интеграции с порталом). Сейчас таких роутов в
  проекте нет (IframeLayout отложен), но как только они появятся, инсталляцию
  с реальными данными клиента через них выставлять в интернет **нельзя**.
- Публичным остаётся только `/up` (health check). `/` перенаправляет на
  `/dashboards/overview` (гость дальше попадает на `/login`). Встроенные
  роуты `storage/{path}` выключены (`serve => false` у диска `local`).

## 2. Для production

- HTTPS обязателен;
- `SESSION_SECURE_COOKIE=true` (cookie сессии только по HTTPS);
- `APP_DEBUG=false`, `APP_ENV=production`, уникальный `APP_KEY`.

## 3. Как создать пользователя

Регистрации нет, пользователей создаёт администратор из консоли:

```bash
php artisan users:create anna@example.com --name="Анна"     # в Sail: ./vendor/bin/sail artisan users:create ...
```

Пароль (минимум 12 символов) запрашивается интерактивно с подтверждением и
не передаётся аргументом или опцией, чтобы не попасть в историю shell.
Email приводится к нижнему регистру. Команда только создаёт: существующего
пользователя она не изменяет и не перезаписывает.

## 4. Смена пароля

```bash
php artisan users:password anna@example.com     # в Sail: ./vendor/bin/sail artisan users:password ...
```

Пользователь должен существовать. Новый пароль (минимум 12 символов)
запрашивается интерактивно с подтверждением и не передаётся аргументом или
опцией. Старый пароль перестаёт работать сразу; уже открытые сессии команда
не завершает.

## 5. Обратный прокси (trusted proxies)

Лимитер входа считает попытки по паре email + IP клиента. Если приложение
стоит за обратным прокси (nginx, Traefik, балансировщик) и доверенные прокси
не настроены, Laravel видит IP самого прокси, и **все клиенты считаются одним
IP** — 5 неудачных попыток от любого пользователя блокируют вход этого email
для всех.

Настройка под конкретную инсталляцию — в `bootstrap/app.php`:

```php
->withMiddleware(function (Middleware $middleware): void {
    $middleware->trustProxies(at: ['10.0.0.5']);   // IP/CIDR вашего прокси; '*' — только если прокси единственная точка входа
})
```

Прокси должен передавать `X-Forwarded-For`/`X-Forwarded-Proto`. Не доверяйте
`'*'`, если приложение достижимо в обход прокси: клиент сможет подделать свой IP
и обходить лимитер.
