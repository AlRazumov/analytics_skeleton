# Этап 28: карточка товара — отчёт

## 1. Что сделано

Страница `/dashboards/products/{id}` — все метрики одного товара: шапка
(название, код, категория, ABC/XYZ-класс), показатели выбранного месяца,
график и таблица выручки/штук за 12 месяцев, склады. Названия товаров в
таблицах топа, неликвидов, риска дефицита, оборачиваемости и перемещений
ведут на карточку за тот же месяц.

| Слой | Файл | Что |
|---|---|---|
| widgets (контракт) | `Core/Widgets/Contracts/ProductMetricsRepository.php` | `forProduct(metric, id, periodKeys)` — строки товара по периодам; `forProductWarehouses(metric, id, periodKey)` — строки его пар товар × склад |
| widgets (контракт) | `Core/Widgets/Contracts/ProductCategoryResolver.php` | `categoryOf(id)` — категория товара по справочнику |
| widgets | `Core/Widgets/ProductCardProvider.php`, `DTO/ProductCardData.php`, `DTO/ProductMonthRow.php`, `DTO/ProductWarehouseRow.php` | сборка карточки и графика выручки; только чтение снэпшотов |
| репозитории | `EloquentProductMetricsRepository`, `DbProductCategoryResolver::categoryOf` | строки товара — по unique-индексу; пары — по индексу месяца метрики с фильтром `split_part(entity_id, ':', 1)` (как в `ProductCategoryFilter`) |
| presentation | `ProductCardController`, `dashboards/product.blade.php`, `components/widgets/product-link.blade.php`, пять табличных компонентов | страница и ссылки |
| конфиг | `config/analytics.php` | флаг `features.product_card` (`ANALYTICS_FEATURE_PRODUCT_CARD`), `display.product_history_months` (12) |
| docs | `docs/features.md`, `docs/demo.md` | флаг, настройка, строка в «Что где видно», ограничение мока |

## 2. Решения

| Вопрос | Решение | Почему |
|---|---|---|
| Какой месяц по умолчанию | последний с выручкой в хранилище (как на «Топе товаров»); `?period=` и переключатель — по месяцам выручки, оборачиваемости, неликвидов и дней до обнуления | одна логика «последнего периода» на страницах товаров |
| Месяц без строки выручки товара | в рассчитанном месяце (есть выручка хоть одного товара) — 0; нерассчитанный месяц в динамике не показывается, база сравнения — нет | «продаж не было» и «данных нет» — разные вещи (как у YoY на обзоре) |
| Изменение выручки | к предыдущему месяцу; база 0 или не рассчитана — без процента | как в сравнениях `MetricsComparisonRepository` |
| ABC/XYZ | из последнего расчёта классификации, с подписью периода, а не из выбранного месяца | классификация пишется за один период (этап 05/11) |
| Склады | сначала пары с продажами по возрастанию дней до обнуления, затем склады с остатком без продаж (`stock_no_demand`) по убыванию остатка | сверху — то, что скоро закончится |
| Товар не в справочнике | карточка — 404; в таблицах такой товар (название = id — так резолверы отдают отсутствующее название) без ссылки | страница строится от справочника; ссылка в 404 хуже её отсутствия |
| Флаги | карточка и ссылки — `product_card`; блоки внутри — флагами своих страниц (`turnover`, `dead_stock`, `stockout_risk`) | выключенный виджет не всплывает в другом месте |
| Отдельный контракт вместо расширения `MetricsSnapshotRepository` | `ProductMetricsRepository` | запросы «по одной сущности» не нужны остальным виджетам; фейки существующего контракта в тестах не меняются |

## 3. Тесты

`tests/Feature/Dashboards/ProductCardTest.php` (8 тестов):

- показатели последнего месяца, ABC/XYZ, категория; динамика пропускает
  нерассчитанный месяц и даёт 0 в рассчитанном без продаж товара; склады
  отсортированы, склад без продаж — последним, пары другого товара с похожим
  id (`p10`) не попадают;
- изменение выручки: база не рассчитана → нет; база 0 → нет процента; иначе процент;
- неликвид (в т.ч. «не меньше N» при `no_sales_in_lookback`), потерянные продажи, «без категории»;
- 404: неизвестный товар, неверный `?period`, выключенный флаг;
- пустое состояние до первого расчёта, переключатель месяцев;
- блоки скрываются флагами; ссылки на карточку из топа, оборачиваемости и
  остатков за тот же месяц, у товара вне справочника ссылки нет, при
  выключенном флаге ссылок нет.

`FeatureMiddlewareTest` дополнен новым флагом. Полный прогон (включая slow),
Pint и PHPStan — зелёные.

Проверено в браузере на dev-данных (Small): страница с графиком и таблицами
рендерится; провайдер — ~25–50 мс. На Large не мерилось: чтение пар идёт
по индексу `(metric_key, period_type, period_start, value)` с фильтром по
товару — просматриваются строки одного месяца метрики.

## 4. Что осталось

- Мок генерирует сделки и движения склада независимо (известно с этапа 06):
  на карточке это впервые видно рядом — у товара сценария неликвидов
  (`prod-1`) выручка месяца соседствует с «продано 0 шт.» и «неликвид».
  На реальных данных такого быть не должно; согласование сделок и движений
  в моке — отдельный этап, если демо будут показывать по карточкам.
- Вне этапа (см. `stages/stage-28-product-card.md`): рекомендации
  перемещений по товару, поиск товара по названию, CSV карточки, продавцы
  товара.
