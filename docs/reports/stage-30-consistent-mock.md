# Этап 30: согласованный мок — отчёт

## 1. Что сделано

Сделки MockAdapter больше не генерируются отдельно от склада: каждое движение
`sale` даёт сделку с той же датой и суммой «штуки × цена товара»; возврат —
приход на склад и сделку с минусом. Выручка, проданные штуки, остатки,
неликвиды и дни до обнуления на страницах теперь описывают одну и ту же
историю (на этапе 28 карточка `prod-1` показывала выручку 5 093 при «продано
0 шт.» и неликвиде).

| Файл | Что |
|---|---|
| `app/Adapters/MockAdapter.php` | `fetchDeals` — из `movementsFor` (`dealOf`, `priceOf`); продавец — `sellerFor` (хэш seed/товар/день, кэш работающих продавцов по дню); сезонный множитель спроса обычных товаров (`demandMultiplier`); `lost_sales` — нет продаж в последнем месяце; `returnsMovements` — возвраты последнего месяца; общие экземпляры дат (`momentOf`) и id товара; `manifest()` считается один раз |
| `app/Adapters/Mock/MockDataProfile.php` | убран `dealsPerMonth()` — число сделок теперь следствие продаж |
| `tests/Unit/Adapters/MockConsistencyTest.php` | новый: продажа ↔ сделка, одна цена на товар, возврат ↔ сделка-возврат (тот же продавец, та же сумма со знаком минус), неликвиды и потерянные продажи в сделках, новогодний пик |
| тесты мока | `MockDealsWindowTest` — эталон переснят (было/стало в комментарии); `MockImbalanceTest`, `MockReturnsTest`, `CategoryFilterTest` — под новую модель (§3) |
| docs | `README.md`, `config/analytics.php` (пик памяти), `docs/demo.md` (ограничение снято, как считается выручка), roadmap (стенд: нужен пересчёт) |

## 2. Решения

| Вопрос | Решение | Почему |
|---|---|---|
| Что первично | движения склада; сделки — их денежное отражение | сценарии остатков (неликвиды, дисбаланс, дни до обнуления) заданы точно на движениях и проверяются по манифесту; у `Deal` нет количества — из сделок штуки не вывести |
| Цена | одна на товар на всю историю, 5,00–500,00 (seed) | выручка = штуки × цена проверяется напрямую; скидки — не цель мока |
| Сделок на продажу | одна (продажа товара на складе за день — одно движение) | как у движений; объём на Medium ~9 500 сделок в месяц вместо 5 000 — тот же порядок |
| Продавец | хэш (seed, товар, день продажи), а не общий поток случайных чисел | сделки любого диапазона совпадают побайтно; возврат получает продавца своей продажи без поиска |
| Сезонность выручки | новогодний множитель (ноябрь 1,3, декабрь 1,8, январь 1,2) к продажам обычных товаров; у сценария `seasonal` — прежняя волна | раньше множитель был к числу сделок; иначе общая выручка стала бы ровной |
| Потерянные продажи | в последнем месяце у товара сценария нет продаж со склада, остаток есть | тот же эффект для `LostSalesCalculator`, что раньше в сделках |
| Возвраты | в последнем месяце каждая продажа товара сценария возвращается (приход на тот же склад в 14:00 случайного дня до конца истории, `meta.return_of_day`); у каждого второго — ещё и последняя продажа предыдущего месяца | тот же манифест: нетто месяца 0 или минус сумма возвращённой продажи; товар возвращается на склад |
| Тип движения возврата | `receipt` с `meta.return_of_day` | отдельного типа в контракте нет; признак возврата в `Deal` ждёт клиента (этап 24) |

## 3. Изменённые тесты

- `MockDealsWindowTest`: эталон — Small 12 882 сделки / 13 011 698,01,
  Medium 229 293 / 234 987 286,48 (было 2 712 / 681 782,05 и 133 233 /
  33 585 617,71). Проверка «без возвратов — прежний отпечаток» убрана: обычные
  сделки теперь другие по построению.
- `MockImbalanceTest` («остальные товары те же без сценария»): при
  отключении дисбаланса сдвигаются id следующих сценариев; раньше у
  `lost_sales` и `returns` не было своих движений, теперь есть — из сравнения
  исключены все четыре сдвигаемых сценария.
- `MockReturnsTest`: движения товаров сценария = обычные + приходы-возвраты
  (сценарий только добавляет возвраты).
- `CategoryFilterTest` (ABC/XYZ по категориям): неликвид без продаж за окно
  класса не получает — раньше случайные сделки давали выручку и неликвидам.

## 4. Замеры

| | До | После |
|---|---|---|
| `fetchDeals` за всю историю, Medium | 1,7 с | 3,2 с |
| `fetchDeals` за всю историю, Large | 22,9 с (1,2 млн) | 33 с (2,2 млн) |
| `metrics:calculate` Large, 12 месяцев (БД `perf`) | 168 с, пик 650 МБ | 164 с, пик 522 МБ |
| Полный прогон тестов | 161 с | 190 с |

Первый замер после переделки дал пик 938 МБ: сделок вдвое больше, а сервис
расчёта держит их массивом. Общие экземпляры `DateTimeImmutable` на (день, час)
и строки id товара вернули пик ниже прежнего.

Проверено на dev-БД (Medium, `metrics:calculate`): карточка `prod-1` — продажи
до мая, с июня выручка и штуки 0, «100 дней без продаж — неликвид»; цена
единицы во всех месяцах одна (451,53); ноябрь–декабрь — пик продаж.

Полный прогон (включая slow), Pint и PHPStan — зелёные.

## 5. Что осталось

  если понадобятся для демо.
- Объёмы профилей по-прежнему ориентировочные (калибровка — при клиенте).
