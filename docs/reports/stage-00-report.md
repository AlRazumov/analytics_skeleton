# Отчёт: Этап 00 (частичный)

## Статус
Этап **не завершён**. Roadmap оставлен как `in progress`. Выполнена
только документационно-организационная часть; установка Laravel и
всё, что от неё зависит (namespace-директории, Pest, миграция), —

## Что сделано
- Инициализирован git-репозиторий в корне проекта (`git init`).
- Первый коммит: `CLAUDE.md` + `docs/` (roadmap, stage-файлы).

## Что отложено и почему
Изначально планировалось поднять Laravel-проект локально через
`composer create-project laravel/laravel`. Попытка была предпринята
(во временной директории вне репозитория), инсталлятор Laravel
успешно доехал до шага `php artisan migrate`, но упал с ошибкой:

```
could not find driver (Connection: sqlite, Database: database/database.sqlite, ...)
```

Диагностика показала: на машине не установлен ни один PDO-драйвер
(`pdo_sqlite`, `pdo_mysql`, `pdo_pgsql` — все отсутствуют, есть только
базовый `PDO`). Установка `php8.3-sqlite3` требует `sudo`, а
passwordless sudo недоступен.

По согласованию с пользователем: полноценная установка Laravel
переносится на момент, когда будет поднят Laravel Sail (Docker) —
там драйверы (по умолчанию SQLite) будут внутри контейнера, и не
понадобится править системный PHP хостовой машины. Временная
директория с частично установленным Laravel (`laravel-new` в
scratchpad) удалена — в репозиторий она не попала.

Соответственно перенесены на подэтап после подъёма Sail:
- инициализация самого Laravel-проекта;
- директории `app/Core/`, `app/Adapters/`, `app/Widgets/`,
  `app/Presentation/` с `.gitkeep`;
- установка и проверка Pest (`php artisan test` / `./vendor/bin/pest`);
- миграция `metrics_snapshots` (создание, up/down-прогон).

## Решения, которые потребуются позже (пока не приняты)
Эти вопросы были заданы в исходном промпте этапа 00, но т.к. миграция
ещё не пишется — фиксирую их здесь, чтобы не потерять к моменту, когда
дойдём до реальной миграции:

- **entity_id**: нужно решить `unsignedBigInteger` vs `string`. Строка
  вероятнее — Bitrix24 отдаёт числовые ID как строки в REST-ответах, а
  1С использует GUID-подобные строковые идентификаторы. Числовой тип
  плохо подойдёт для 1С. Предварительная рекомендация: `string`
  (с адекватной длиной, например 191, чтобы влезть в индекс на
  MySQL с utf8mb4).
- **value**: скаляр (`decimal`) или `json`. Если у части метрик
  возможны составные значения (например, разбивка по категориям
  внутри одной метрики) — нужен `json`. Если все метрики этапов 01-04
  строго скалярные — `decimal` проще и быстрее для агрегаций/сортировок.
  Требует уточнения на этапе 01, когда будет ясен набор реальных
  метрик под MockAdapter.
- **period**: `string` в формате `'YYYY-MM'`/`'YYYY-MM-DD'` выглядит
  практичнее чистого `date`, т.к. агрегация может быть не только
  по дням/месяцам, но и по произвольным периодам отчётности; `date`
  ограничивает гранулярность днём. Предварительная рекомендация:
  `string`, но нужно решить это перед написанием миграции.
